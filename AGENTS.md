# AGENTS.md

> Operating manual for AI assistants and agents that interact with this
> repository. Read this *before* touching anything. It defines how to behave,
> what is safe to touch, what is not, and how to verify your work.

This document is for **AI agents** (Hermes, Claude Code, Codex, OpenCode,
Cursor, Aider, Cline, etc.) operating *inside* this repository. Humans can
read it too, but the tone is deliberately directive.

---

## 1. What this repo is

This is the **Java / Spring Boot** reference implementation of the **MSC
(Model Solution Client)** protocol (`draft-msc-protocol-00`).

The HTTP contract is **contract-first**: `openapi.yaml` is the single
source of truth, and Spring controllers + DTOs are generated from it on
every build via the official `openapi-generator-maven-plugin`.

You are expected to understand the **intent** of the project before editing
it. If you only read the code, you will miss the protocol semantics.

| File | Purpose |
|------|---------|
| `msc-rfc-protocol.md` | The protocol specification. **Read-only authoritative spec.** |
| `openapi.yaml` | OpenAPI 3.1 contract. Source of truth for HTTP API. |
| `pom.xml` | Maven build. Defines generator config, deps, plugins. |
| `src/main/java/io/msc/` | Hand-written code: domain, security, service, storage, controllers. |
| `target/generated-sources/` | **Generated** from `openapi.yaml`. Do not edit; do not commit. |
| `payload.json`, `payload-alt.json` | (gitignored) example contributions for the smoke test. |
| `scripts/smoke_test.py` | Python client that signs and posts a payload. |
| `README.md` | Human-facing quickstart. |

## 2. Non-negotiable rules

### 2.1 Never invent protocol semantics

If a behaviour is not defined in `msc-rfc-protocol.md`, **do not add it on a
whim**. Either:

1. Extend the RFC first (open a draft change in the same repo), **then**
   implement it.
2. Or surface the gap to the user and ask how to proceed.

Do not silently introduce new endpoints, headers, payload fields, or status
codes. The reference impl must match the RFC; the RFC must drive the impl.

### 2.2 Never break the wire format

The payload in `io.msc.api.generated.model.*` (regenerated from
`openapi.yaml`) **is** the wire format. If you change field names, types,
regex patterns, or required-ness in `openapi.yaml`, you are breaking the
protocol. Treat that like a breaking API change:

- Update `msc-rfc-protocol.md` first.
- Add a `CHANGELOG.md` entry.
- Bump the `msc_version` (currently `"0.1"`).
- Update `README.md` and verify the generated code still compiles.

### 2.3 Never edit generated code

Files under `target/generated-sources/` are produced by
`openapi-generator-maven-plugin` on every build. Editing them is pointless
(they will be overwritten) and breaks diff hygiene.

The one exception is `io.msc.api.generated.ApiUtil.java`, which is **not**
generated but lives in that package. It is a no-op stub the generator calls
into for example responses. If you need it to do something real, modify
that hand-written file (it is **not** in `target/`).

### 2.4 Cryptography is the security boundary

`io.msc.security.Ed25519Verifier.java` defines how identities sign and
verify. Do **not**:

- Switch to RSA, ECDSA, HMAC, JWT-only, or any other scheme without an RFC
  update.
- Skip signature verification in any code path, even for "internal"
  endpoints.
- Store the private key in plain text anywhere other than the user's local
  keyfile generated by `scripts/smoke_test.py`.
- Compute the signature over anything other than the exact UTF-8 bytes of
  the request body. Spring serialises the body via Jackson after
  `@RequestBody` parses it; to verify you must read the raw bytes before
  Spring sees them. This is what `CachedBodyFilter` does — do not remove
  it.

### 2.5 The audit log is append-only by contract

`MscRepository.appendAudit(...)` must never UPDATE or DELETE existing rows.
The RFC §6 requires append-only. If you need a "correction", add a new
audit row that references the old one.

### 2.6 No silent dependencies on user data

- Do not change `user_attribution` defaults to anything other than
  `"anonymous"`.
- Do not add any field that leaks the user's real identity without
  explicit opt-in.
- `session_hash` in `Context` is a one-way SHA-256 hash. Do not weaken it
  to a reversible encoding.

### 2.7 Key registration has no admin endpoint, by design

The reference server does **not** expose an HTTP endpoint for registering
origin public keys. Operators must `INSERT` directly into the `keys`
table (or use the smoke test script, which does it under the hood).

If you are tempted to add `/msc/keys` as a public endpoint, **stop and ask
the user**. Authentication for key registration is its own design problem
and is *Future Work* in the RFC.

## 3. How to operate

### 3.1 Read order (every session, every time)

```
msc-rfc-protocol.md   ← the contract (Section 5 is the wire format)
README.md             ← what the repo does for humans
AGENTS.md             ← this file
openapi.yaml          ← the HTTP contract that drives generation
pom.xml               ← generator config, dependencies, Java version
src/main/java/io/msc/ ← hand-written code (skim, don't read every line)
scripts/smoke_test.py ← the canonical end-to-end demo
```

If you skip step 1 you will break §2.1. If you skip step 4 you will be
unaware of which fields are wire-typed, which are enums, etc.

### 3.2 Environment

The repo expects:

- JDK 21+ (the parent POM and the `maven-compiler-plugin` default to 21).
- The bundled `mvnw` Maven Wrapper for builds.
- Python 3 + `cryptography` for the smoke test (the test does not
  depend on Python version).

Always use `./mvnw` rather than a global `mvn`. The wrapper pins the Maven
version so CI and local dev match.

### 3.3 How to run things

```bash
# Run the server
./mvnw -B -ntp spring-boot:run

# Build a runnable jar
./mvnw -B -ntp clean package

# End-to-end smoke test
./mvnw spring-boot:run &
python3 scripts/smoke_test.py
python3 scripts/smoke_test.py payload-alt.json    # try the queueing path
```

### 3.4 How to regenerate after changing the contract

If you edit `openapi.yaml`, the next `./mvnw` invocation will regenerate
the controllers and DTOs automatically (the `openapi-generator-maven-plugin`
is bound to the `generate-sources` phase).

To regenerate **explicitly** (useful for IDE preview):

```bash
./mvnw -B -ntp clean generate-sources
```

## 4. Testing discipline

This project does **not** ship JUnit tests (removed deliberately to keep
the reference minimal). The end-to-end smoke test in
`scripts/smoke_test.py` is the canonical verification.

Before declaring a task done, **all** of these must be true:

1. `./mvnw -B -ntp clean package` succeeds with no errors.
2. `python3 scripts/smoke_test.py payload.json` returns HTTP 202 with
   `status: accepted`.
3. `python3 scripts/smoke_test.py payload-alt.json` returns HTTP 202
   with `status: queued`.
4. `GET /msc/audit` shows both contributions with their decisions.
5. If you touched `openapi.yaml`, the generated sources compile and the
   smoke test still passes against the regenerated client interface.

### 4.1 When adding a new endpoint

1. Add the path, method, parameters, request body and response codes
   to `openapi.yaml`.
2. Run `./mvnw clean generate-sources` and inspect the generated
   interface in `target/generated-sources/.../api/<Tag>Api.java`.
3. Add (or extend) a `@RestController` that `implements` the generated
   interface.
4. Add a smoke test invocation in `scripts/smoke_test.py` (or a new
   script) that exercises the new endpoint.
5. Update `README.md` to document the endpoint.

## 5. Common pitfalls (read these before you get stuck)

| Pitfall | Why it bites you | Fix |
|---------|------------------|-----|
| Editing files under `target/` | They are regenerated on every build; your changes vanish. | Edit `openapi.yaml` or hand-written code in `src/main/java/`. |
| Switching from `String` to an enum in a generated DTO without updating tests | `contains("comment")` won't compile against `List<AcceptedTypesEnum>`. | Use `.extracting(Object::toString)` or convert via `.value()`. |
| Removing `CachedBodyFilter` | The signature is computed over the raw body bytes; without caching, Spring re-encodes the JSON and the signature breaks. | Keep the filter. It is essential. |
| Adding `public KeyPair` helpers in tests that assume I2P `EdDSAPublicKey` | Java 21+'s SunEC native provider returns a different concrete class. | Extract raw bytes via `PublicKey.getEncoded()` (X.509) instead of casting. |
| Expecting `:memory:` SQLite to share state across pooled connections | It does not, unless you also pass `cache=shared` and keep a connection open. | Use a file path; the default `./msc.db` is fine. |
| Committing `msc.db` or `payload.json` | They contain runtime data and example payloads. | `.gitignore` excludes both; keep it that way. |
| Adding an admin endpoint for key registration | Auth design is non-trivial and is Future Work in the RFC. | Keep `INSERT INTO keys` direct in the DB. |

## 6. When you should NOT use this repo

- For high-throughput production traffic. The reference is single-process,
  SQLite-backed, with no horizontal-scaling story.
- For production signing infrastructure. The crypto is correct but key
  storage and rotation are the operator's responsibility.
- As a public-facing moderation UI. There is no UI; only HTTP API +
  Python CLI smoke test.

If the user asks for any of these, surface the limitation and propose a
deployment plan rather than hacking the reference impl into production.

## 7. Escalation triggers (ask the human, do not guess)

- A request to remove the audit log or any "decision" record.
- A request to skip signature verification "for performance".
- A request to expose the private key in logs, error messages, or HTTP
  responses.
- A request to change the protocol semantics in code without updating
  the RFC.
- A request to integrate with a real forum (Discourse, Reddit, etc.) —
  this needs the forum's API credentials, moderation rules, and legal
  review.

## 8. Style conventions in this repo

- Java 21+ (records, sealed types if helpful, `var` where it improves
  readability). Maven compiler is configured for Java 21.
- No third-party deps beyond: FastAPI starter, validation starter,
  SQLite JDBC, I2P EdDSA, ULID-creator. (No Spring Data JPA, no Lombok.)
- Comments only where the code is non-obvious. Self-documenting preferred.
- Tests live in `scripts/`, not in `src/test/java/`. (No JUnit tests;
  smoke test is Python.)

## 9. Quick reference: file → responsibility

| You want to... | Touch this |
|----------------|------------|
| Change a payload field | `openapi.yaml` **and** `msc-rfc-protocol.md` (section 5) |
| Add a new endpoint | `openapi.yaml` **and** a new `@RestController` in `src/main/java/io/msc/api/` |
| Add a new CLI subcommand | `scripts/smoke_test.py` (or a new script) |
| Add a DB column | `MscRepository.SCHEMA` and a new method |
| Change signature algorithm | **STOP.** Update RFC section 5.3 first, then `Ed25519Verifier.java`. |
| Change the auto-accept threshold | `ContributionService.AUTO_ACCEPT_CONFIDENCE` and the `AUTO_REJECT_PATTERNS` list |
| Tweak rate limits | `ContributionService.RATE_LIMIT_PER_IP` / `RATE_LIMIT_PER_ORIGIN` |
| Add a moderator UI | New file `ui/...`; do not touch `server.py` endpoints |
| Update the smoke test | `scripts/smoke_test.py` |

## 10. End-of-task checklist

Run through this before reporting "done":

- [ ] `./mvnw -B -ntp clean package` succeeds.
- [ ] `python3 scripts/smoke_test.py payload.json` → HTTP 202 / `accepted`.
- [ ] `python3 scripts/smoke_test.py payload-alt.json` → HTTP 202 / `queued`.
- [ ] `GET /msc/audit` shows both contributions.
- [ ] If you touched `openapi.yaml`, the generated sources recompile
      cleanly and the controllers still bind.
- [ ] No generated artefacts (`target/`, `msc.db`, `payload*.json`)
      left in a commit-ready state.
- [ ] No secrets, private keys, or tokens committed.
- [ ] `README.md` reflects any new endpoint or behaviour change.
